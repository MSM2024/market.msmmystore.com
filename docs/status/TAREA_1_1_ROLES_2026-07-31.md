# TAREA 1.1 — Unificar taxonomía de roles (P0)

**Fecha:** 2026-07-31
**Estado:** ✅ Código implementado y verificado · ⏳ Validación e2e pendiente (requiere claves Supabase reales, Fase 0)

## Problema (de la auditoría real 2026-07-30)

Tres taxonomías de rol en conflicto:

| Fuente | Roles | Problema |
|---|---|---|
| `00003` enum `user_role` | customer, seller, vip, referrer, supplier, support, finance, admin, superadmin | Sin `owner` |
| `00036` CHECK `profiles_role_check` + funciones | owner, superadmin, finance, kyc, inventory, support, auditor, vendor, customer | **Sin `admin` ni `seller`** → las políticas RLS del marketplace que usan `role IN ('admin','superadmin')` o `('seller',...)` no pueden coincidir con ningún perfil |
| `00041` seeds | `role='owner'` y `role='admin'` | `admin` NO es válido bajo el CHECK de 00036 → **el UPDATE fallaba** |

Consecuencias verificadas:
- `src/proxy.ts:141` excluía `owner` del acceso a `/admin` → Don Miguel no podría entrar.
- `is_admin_or_superadmin()` (00036) no incluía `admin` → ~40 políticas "Admin can…" no reconocían el rol admin original.
- Tablas del marketplace sin política admin basada en función (categorías, proveedores, tiendas, productos, conectores, historial de precios) bloqueaban a `owner`.
- `marketplace_order_items`, `marketplace_order_status_history` y `marketplace_tracking_events` no tenían ninguna política admin.

## Solución aplicada

### Migración nueva `supabase/migrations/00037_role_taxonomy_fix.sql`
(Usa el hueco de numeración libre entre 00036 y 00038 → se aplica **antes** de 00041, evitando su fallo.)

1. **CHECK unificado de `profiles`**: 14 roles = unión de las tres taxonomías
   `owner, superadmin, admin, finance, support, supplier, seller, vip, referrer, customer, kyc, inventory, auditor, vendor`
2. **`is_admin_or_superadmin()` y `user_is_admin(uid)`**: añadido `'admin'` (se conservan los roles staff de 00036: finance/kyc/inventory/support/auditor — no se reduce ningún acceso ya otorgado).
3. **`user_roles.role`**: migrada de enum (sin `owner`) a `TEXT` + CHECK unificado.
4. **Políticas inline del marketplace recreadas con `owner`**: categorías (3), proveedores (3), tiendas (2: select_admin + insert_seller), productos (2), provider_products (1), provider_prices (2), provider_inventory (2), price_history (1), orders_update_admin, payments_update_admin, shipments_update_admin.
5. **Nuevas políticas admin** (antes inexistentes): `order_items_select_admin`, `status_history_select_admin`, `tracking_select_admin`.
6. **Seeds idempotentes por email** de Don Miguel: `cm8msm@gmail.com` → owner, `msmmystore@gmail.com` → admin (cubre también el caso de que 00041 ya se hubiera aplicado con el UPDATE fallido).

### Código
- `src/proxy.ts`: gate de `/admin` acepta `owner`; gate de vendedor (`/dashboard`, `/marketplace/vender`, `/marketplace/crear-tienda`) acepta `owner`.
- `src/lib/auth.ts`: `UserRole` ampliado con `kyc | inventory | auditor | vendor`; `ROLE_HIERARCHY` incluye los 4 roles huérfanos (evita NaN en `canAccess`/`requireRole`).
- `src/lib/unified-identity/config.ts`: `ADMIN_ROLES`/`ADMIN_ACCESS_ROLES` incluyen `admin`.
